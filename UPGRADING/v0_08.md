# Upgrading from `v0.7.3` to `v0.8.0`

Version `0.8.0` includes both performance and security enhancements that require your data to be migrated to a new database layout. Luckily version `0.7.3` includes a migration tool which should make this process much easier than previous upgrades. In addition to the new layout, you will have to change the systemd service file to use the `CAP_NET_BIND_SERVICE` capability.

## Preparation
- Upgrade to version `0.7.3` if you haven't already. If you are on a version previous to `0.7.0`, you will have to do a manual migration of your data using the Command-line Interface.
- Create a directory where your data will be exported to, for example `/opt/NordibleMail-mail/export`.

## Systemd service upgrade (Linux only)
- Stop the `v0.7.3` installation:
  ```bash
  $ sudo systemctl stop NordibleMail-mail
  ```
- Update your systemd file to include the `CAP_NET_BIND_SERVICE` capability. Open the file `/etc/systemd/system/NordibleMail-mail.service` in a text editor and add the following lines under the `[Service]` section:
  ```
  User=NordibleMail-mail
  Group=NordibleMail-mail
  AmbientCapabilities=CAP_NET_BIND_SERVICE
  ```
- Reload the daemon:
  ```bash
  $ systemctl daemon-reload
  ```
- Do not start the service yet.

## Data migration
- Stop NordibleMail and export your data:

  ```bash
  $ sudo systemctl stop NordibleMail-mail
  $ sudo /opt/NordibleMail-mail/bin/NordibleMail-mail --config /opt/NordibleMail-mail/etc/config.toml --export /opt/NordibleMail-mail/export
  $ sudo chown -R NordibleMail-mail:NordibleMail-mail /opt/NordibleMail-mail/export
  ```

  or, if you are using the Docker image:

  ```bash
  $ docker stop NordibleMail-mail
  $ docker run --rm -v <NordibleMail_DIR>:/opt/NordibleMail-mail -it NordibleMail-mail /opt/NordibleMail-mail/bin/NordibleMail-mail --config /opt/NordibleMail-mail/etc/config.toml --export /opt/NordibleMail-mail/export
  ```
- Backup your `v0.7.3` installation:
  - If you are using RocksDB or SQLite, simply rename the `data` directory to `data-backup`, for example:
    ```bash
    $ mv /opt/NordibleMail-mail/data /opt/NordibleMail-mail/data-backup
    $ mkdir /opt/NordibleMail-mail/data
    $ chown NordibleMail-mail:NordibleMail-mail /opt/NordibleMail-mail/data
    ```
  - If you are using PostgreSQL, rename the database and create a blank database with the same name, for example:
    ```sql
    ALTER DATABASE NordibleMail RENAME TO NordibleMail_old; 
    CREATE database NordibleMail;
    ```
  - If you are using MySQL, rename the database and create a blank database with the same name, for example:
    ```sql
    CREATE DATABASE NordibleMail_old;
    RENAME TABLE NordibleMail.b TO NordibleMail_old.b;
    RENAME TABLE NordibleMail.v TO NordibleMail_old.v;
    RENAME TABLE NordibleMail.l TO NordibleMail_old.l;
    RENAME TABLE NordibleMail.i TO NordibleMail_old.i;
    RENAME TABLE NordibleMail.t TO NordibleMail_old.t;
    RENAME TABLE NordibleMail.c TO NordibleMail_old.c;
    DROP DATABASE NordibleMail;
    CREATE database NordibleMail;
    ```
  - If you are using FoundationDB, backup your database and clean the entire key range.
- Download the `v0.8.0` mail-server for your platform from the [releases page](https://github.com/NordibleMaillabs/mail-server/releases/latest/) and replace the binary in `/opt/NordibleMail-mail/bin`. If you are using the Docker image, pull the latest image.
- Import your data:

  ```bash
  $ sudo -u NordibleMail-mail /opt/NordibleMail-mail/bin/NordibleMail-mail --config /opt/NordibleMail-mail/etc/config.toml --import /opt/NordibleMail-mail/export
  ```

  or, if you are using the Docker image:
  
  ```bash
  $ docker run --rm -v <NordibleMail_DIR>:/opt/NordibleMail-mail -it NordibleMail-mail /opt/NordibleMail-mail/bin/NordibleMail-mail --config /opt/NordibleMail-mail/etc/config.toml --import /opt/NordibleMail-mail/export
  ```
- Start the service:
  ```bash
  $ sudo systemctl start NordibleMail-mail
  ```

  Or, if you are using the Docker image:
  ```bash
  $ docker start NordibleMail-mail
  ```
